# Product Manager: React + ASP.NET Core + SQL Server CRUD

A small full-stack app for managing products (Create, Read, Update, Delete).

```
┌──────────────────────┐   HTTP + JSON    ┌──────────────────────────┐   EF Core / SQL   ┌──────────────┐
│ React (Vite)         │ ───────────────► │ ASP.NET Core Web API     │ ────────────────► │ SQL Server   │
│ localhost:3000       │ ◄─────────────── │ localhost:5058           │ ◄──────────────── │ ProductDb    │
│ Axios, Bootstrap     │                  │ ProductsController       │                   │ dbo.Products │
└──────────────────────┘                  └──────────────────────────┘                   └──────────────┘
```

## Running it

Prerequisites: .NET 10 SDK, Node.js 20+, SQL Server (Express/Developer/LocalDB).

```powershell
# 1. Backend (terminal 1)
cd crud-app\ProductApi
dotnet tool restore            # installs the local dotnet-ef tool
dotnet ef database update      # creates ProductDb + Products table (first time only)
dotnet run                     # API on http://localhost:5058

# 2. Frontend (terminal 2)
cd crud-app\product-client
npm install                    # first time only
npm run dev                    # open http://localhost:3000
```

# Step-by-step walkthrough

## Step 1: Set up the React frontend

```powershell
npm create vite@latest product-client -- --template react
cd product-client
npm install
npm install axios bootstrap
```

- **Vite** is the build tool/dev server. It serves your `.jsx` files instantly and hot-reloads on save.
- **Axios** is an HTTP client (a friendlier `fetch`).
- **Bootstrap** gives ready-made CSS classes (`btn`, `table`, `card`, `row`/`col-lg-4` grid) so the UI is responsive without writing much CSS. It's imported once in `main.jsx`.
- `vite.config.js` fixes the dev port to **3000** so it always matches the API's CORS setting.
- `.env` holds `VITE_API_URL`. Only variables starting with `VITE_` are exposed to browser code, via `import.meta.env.VITE_API_URL`.

## Step 2: Create the ASP.NET Core Web API

```powershell
dotnet new webapi -n ProductApi --use-controllers --no-https
cd ProductApi
dotnet add package Microsoft.EntityFrameworkCore.SqlServer   # SQL Server provider
dotnet add package Microsoft.EntityFrameworkCore.Design      # needed for migrations
dotnet new tool-manifest
dotnet tool install dotnet-ef                                # migrations CLI (project-local)
```

**`Program.cs`** has two halves:

1. **Register services** (`builder.Services...`): these go into the *dependency injection* container.
   - `AddControllers()` enables controller classes.
   - `AddDbContext<AppDbContext>(... UseSqlServer(...))` tells EF Core to talk to SQL Server using the
     connection string from `appsettings.json`. Any controller that asks for `AppDbContext` in its constructor gets one
     automatically, with a new instance per HTTP request.
   - `AddCors(...)` declares that `http://localhost:3000` may call this API. Browsers block cross-origin requests
     (different port = different origin) unless the server opts in. Without this you'd see a CORS error in the
     browser console even though the API itself works.
2. **Build the pipeline** (`app.Use...`): middleware that every request flows through, in order:
   exception handler → CORS → authorization → controllers.

## Step 3: Create the database and table

We use **EF Core Code-First**: you write C# classes and EF generates the SQL.

**`Models/Product.cs`** is the entity. Conventions do most of the work:
- A property named `Id` becomes the **primary key** with `IDENTITY` (auto-increment).
- `[Required]` → `NOT NULL`; `[MaxLength(100)]` → `NVARCHAR(100)`; `string?` → nullable column.
- `[Column(TypeName = "decimal(18,2)")]` stores money precisely.

**`Data/AppDbContext.cs`**: `DbSet<Product> Products` = the `Products` table. `HasData(...)` seeds two rows.

**Connection string** (`appsettings.json`):
```
Server=localhost;Database=ProductDb;Trusted_Connection=True;TrustServerCertificate=True;
```
- `Server=localhost`: the default SQL Server instance. Use `localhost\SQLEXPRESS` for a named Express instance
  or `(localdb)\MSSQLLocalDB` for LocalDB.
- `Trusted_Connection=True`: log in with your Windows account (no password in the file).
- `TrustServerCertificate=True`: accept the local server's self-signed certificate.

**Create the database:**
```powershell
dotnet ef migrations add InitialCreate   # generates Migrations/…_InitialCreate.cs (C# describing the table)
dotnet ef database update                # runs it: creates ProductDb + dbo.Products + seed rows
```
Change the model later? Add another migration (`dotnet ef migrations add AddCategory`) and run `database update` again.

Prefer plain SQL? `database/schema.sql` is the exact script EF ran (generated with `dotnet ef migrations script`).
You can open it in SSMS / Azure Data Studio to see the `CREATE TABLE`.

## Step 4: Implement the CRUD API endpoints

`Controllers/ProductsController.cs`: `[Route("api/[controller]")]` → base URL `/api/products`.

| Operation | HTTP              | Code                                   | Success | Errors       |
|-----------|-------------------|----------------------------------------|---------|--------------|
| Read all  | `GET /api/products`      | `db.Products.ToListAsync()`     | 200     |              |
| Read one  | `GET /api/products/{id}` | `db.Products.FindAsync(id)`     | 200     | 404          |
| Create    | `POST /api/products`     | `Add()` + `SaveChangesAsync()`  | 201     | 400          |
| Update    | `PUT /api/products/{id}` | change properties + `SaveChangesAsync()` | 200 | 400, 404 |
| Delete    | `DELETE /api/products/{id}` | `Remove()` + `SaveChangesAsync()` | 204  | 404          |

Key ideas:
- **Nothing hits the database until `SaveChangesAsync()`.** EF tracks the changes you make to loaded objects and then
  generates the `INSERT`/`UPDATE`/`DELETE`.
- **`async`/`await`** frees the server thread while SQL Server works, so the API can serve more requests at once.
- **DTO (`ProductRequest`) vs entity (`Product`)**: the client sends a DTO containing only the fields it may set.
  This stops a client from overwriting `Id` or `CreatedAt` (this attack is called *over-posting*).
- **Validation**: the `[Required]`, `[StringLength]` and `[Range]` attributes on `ProductRequest` are checked
  automatically because of `[ApiController]`. Invalid input never reaches your method; the client gets
  `400` with `{ "errors": { "Name": ["Name must be 2-100 characters."] } }`.
- **Error handling**: missing records return `404 { message }`. Any unexpected exception (e.g. SQL Server is down)
  is caught by `UseExceptionHandler` and returned as a JSON `500` instead of an HTML page.

## Step 5: Connect React to the API

**`src/api/productService.js`** is the only file that knows URLs. It creates one Axios instance with `baseURL` and
exports one function per endpoint (`getProducts`, `createProduct`, …). Components never call Axios directly.

It also has two error helpers:
- `getErrorMessage(err)` covers three cases: no response (API not running / CORS), our `{ message }` (404), or
  ASP.NET's `{ title }` (400/500).
- `getValidationErrors(err)` converts the API's `{ errors: { Name: [...] } }` into `{ name: "..." }` so each message
  appears under the matching input.

**`App.jsx`** owns the state:
- `products`: the list shown in the table.
- `editing`: the product being edited (`null` means the form is in "add" mode).
- `toDelete`: the product awaiting confirmation (non-null makes the modal visible).
- `alert`: the success/error banner.

Data flow for each operation:
- **Read**: `useEffect` runs once on mount → `getProducts()` → `setProducts(...)` → React re-renders the table.
- **Create**: form submit → client validation → `createProduct()` → append the returned product to state.
- **Update**: click *Edit* → `setEditing(product)` → the form fills in → submit → `updateProduct()` → replace the
  item in state.
- **Delete**: click *Delete* → `setToDelete(product)` → the modal asks for confirmation → `deleteProduct()` → filter
  the item out of state.

After a successful call we update local state instead of reloading the whole list, which keeps the UI fast.

**`ProductForm.jsx`** is used for both Create and Edit:
- It is a *controlled form*: every input's `value` comes from state and `onChange` updates it.
- `validate()` mirrors the server rules for instant feedback. The server **still validates**, because anyone can
  bypass the browser and call the API directly.
- Bootstrap's `is-invalid` + `invalid-feedback` classes show red borders and messages.
- `App` renders it with `key={editing?.id ?? 'new'}`. When the key changes, React throws the old form away and
  creates a fresh one, which is a simple way to reset form state.

## Step 6: Test all CRUD operations

**API alone** (before touching React), using any of:
- `ProductApi/ProductApi.http`: open it in Visual Studio / VS Code (REST Client extension) and click *Send Request*.
- The OpenAPI document at `http://localhost:5058/openapi/v1.json` (import it into Postman to get a ready collection).
- PowerShell:
  ```powershell
  Invoke-RestMethod http://localhost:5058/api/products
  Invoke-RestMethod http://localhost:5058/api/products -Method Post -ContentType 'application/json' `
    -Body '{"name":"USB-C Hub","price":39.5,"quantity":15}'
  ```

**Through the UI** at http://localhost:3000:
1. **Create**: fill in the form → *Add product* → the row appears with a green banner.
2. **Validation**: submit with an empty name or price `0` → red messages under the fields.
3. **Update**: *Edit* on a row (it turns yellow) → change values → *Save changes*.
4. **Delete**: *Delete* → the modal asks for confirmation → *Delete* → the row disappears.
5. **Error handling**: stop the API (Ctrl+C) and click *Refresh* → banner: "Cannot reach the server…".
6. **Check the database**: `SELECT * FROM Products` in SSMS or
   `sqlcmd -S localhost -E -C -d ProductDb -Q "SELECT * FROM Products"`; your changes are really stored.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| "Cannot reach the server" banner | API not running, or `VITE_API_URL` port doesn't match `launchSettings.json` (5058). Restart `npm run dev` after editing `.env`. |
| Browser console: *blocked by CORS policy* | The page origin isn't in `WithOrigins(...)` in `Program.cs`. It must be exactly `http://localhost:3000`. |
| `dotnet ef database update` can't connect | Fix the `Server=` part of the connection string for your instance (`localhost\SQLEXPRESS`, `(localdb)\MSSQLLocalDB`). |
| `Port 3000 is already in use` | Change `server.port` in `vite.config.js` **and** the CORS origin in `Program.cs`. |
